Essay

Cursor still runs this site

October 1, 2026 · AI workflow

Published
October 1, 2026
Topic
AI tooling
Daily driver
Cursor
Also tried
GitHub Copilot CLI

I have been using AI to build and maintain this site, and the journey is in a good place. Cursor is the tool that constructed these static pages and the one I still trust to change them. I recently started using GitHub Copilot CLI. It is a capable terminal agent, but it does not feel as powerful as Cursor.

What “progress” looks like here

TheMindIsWasted is a static site: reviews, a game log, a tech section, and the October horror schedule. There is no app server behind the pages. The work is HTML, CSS, and the discipline of matching a page that already exists. That sounds simple until you are adding a review, a poster treatment, a calendar cell, and the index cards that point at it, all in the same voice.

Cursor is what got that system standing, and it is what keeps it standing. I can hand it a page that already shipped, ask for a change that has to fit the rest of the site, and get a result I can open in a browser and judge. That loop — edit, check, correct — is the whole job. The progress is not that I type less. The progress is that a finished page is a normal outcome.

Why Cursor still feels like the stronger tool

Cursor’s CLI is not a separate product. It is the same agent as the editor: same account, same project, same rules. When I am in the terminal I am still working on this repository, with the layout, the class names, and the pages that have to stay consistent. The agent can read the files, change them, and leave something I can verify.

That is the part that matters for a site like this. A static page is a set of agreements. The hero, the rating, the navigation, and the card on the index all have to agree. Cursor holds that agreement well enough that I am happy to keep using it. I am not shopping for a replacement.

Copilot CLI is capable. It feels smaller.

Copilot CLI is included with every GitHub Copilot plan. It runs in the terminal, spends the same AI credits as Copilot Chat, and sits next to the rest of GitHub: issues, pull requests, and gh. For work that starts on GitHub, that is a sensible place to put an agent.

For maintaining this site, it has not matched Cursor. Sessions feel narrower. Multi-step changes — a new page, the index, the schedule, the styling — do not land with the same confidence. I do not think Copilot CLI is a bad tool. I think it is a different center of gravity, and that center is GitHub, not the long edit that has to survive contact with an existing design.

What the plans actually cost

Neither CLI has its own price. You pay for the platform, and the terminal agent draws from that plan. These are the published individual and team prices as of October 1, 2026. Cursor’s paid plans include a Cursor Models pool and an Other Models pool, then on-demand usage at the model’s API rate. Copilot’s paid plans include a base credit allotment plus a flex allotment GitHub can adjust. Unused credits do not roll over.

Price is not the same thing as power

On the sticker, Copilot is the cheaper entry. Pro is $10 against Cursor Pro at $20, and Copilot Max is $100 against Cursor Ultra at $200. That matters if the work fits inside Copilot’s credit allowance and inside the kind of task Copilot is good at.

Sticker price is not how I choose a tool for this site. If I have to run the session again, the savings disappear. Cursor costs more at the comparable tier, and it is the tool that has actually shipped and maintained these pages. I would rather pay for the loop that finishes.

Where I am leaving it

I am happy with Cursor. It built this site, and it is what I will keep using to maintain the static pages. Copilot CLI stays in the kit for GitHub work, where its home-field advantage is real. For the long edit — the one that has to match the rest of the site — it does not feel as powerful, and I am not going to pretend that a lower price changes that.
